# 小蕾米动作：跨版本维护与验收

更新日期：2026-09-09。适用于本仓库的 Linux 桌面端运行时增强。本文中的“适配”不等于官方支持，也不等于已在每台机器完成视觉验收。

## 1. 结论与边界

采用两层方案：独立 Pet 素材作为长期基础；细分动作使用按客户端版本隔离的适配器。当前公开的 [OpenAI Pets 文档](https://developers.openai.com/codex/pets) 定义 Running、Needs input、Ready、Blocked，以及多任务的状态优先级和减少动态效果行为。该文档未提供可配置“推理/工具/输出 → 自定义帧段”的公开扩展接口。因此不能承诺非官方运行时补丁跨所有未来版本自动有效。

本方案提供的是可诊断、可重放、拒绝不兼容写入、可安全回滚的维护流程。应用升级后先诊断，再决定重装已有适配器或新增适配器。不要禁用应用更新来维持桌宠动作，也不要删除版本检查或只改版本号来强行适配。

## 3. 本次动作修复

本机 `26.901.20858` 已移除旧版独立 frame 模块；状态计算位于浮动 page，图集动画位于 app-initial。旧补丁会报找不到模块。

新适配器完成以下修改：

- 订阅完整会话事件，保留 `petState` 到通知和动画组件的传递，并使该字段参与通知变化判断。
- 将当前打开的普通任务纳入 Pet 活动源；保留语音任务过滤和原有多任务优先级。此活动源改变影响整个浮动托盘，不仅小蕾米。
- 运行中识别活动工具；没有活动工具时按最近一条有意义的 reasoning、agentMessage 或工具事件选状态。忽略末尾统计等元数据，不跨会话或跨 turn 保存粘性工具状态。
- 保持等待输入和失败的原有优先级，完成状态仍依赖官方“已完成且未读”状态；读过完成消息后变待机是正常行为。
- 只对 `custom:xiaoleimi` 的工作、等待、失败和完成动作持续循环，消除“三轮后循环慢速待机尾帧”的表现。其他桌宠仍沿用官方帧序列；它们遇到内部 T/Y 状态时回退为 Running。
- 保留完整图集元数据和翻译描述，不靠删除功能数据腾空间；重新打包 ASAR，并更新偏移、目标文件大小与块校验。其他内嵌文件逐字节不变。

| 状态 | 目标帧（从 0 计数） | 条件 / 限制 |
| --- | --- | --- |
| 思考 T | R7 C0–C2 | 最新有效事件为 reasoning |
| 工具 / 运行 | R7 C3–C5 → R8 C0 | 有运行中工具、最新为工具或运行态缺乏细节 |
| 输出 Y | R6 C0–C5 | 最新有效事件为 agentMessage，包括 commentary 和 final，不仅最终答案 |
| 完成 review | R7 C1–C5 | 官方完成未读状态 |
| 等待 waiting | R6 C0–C5 | 用户输入或批准；视觉上与输出相同 |
| 失败 failed | R5 C0–C7 | 官方失败状态 |
| 待机 idle | R0 原生帧 | 无可展示活动 |

Cloud 活动没有完整本地 turn items 时只提供粗粒度状态。新工具事件类型如果尚未进入识别表，会退回粗粒度状态，需要新增测试后再调整适配器。鼠标悬停、指针方向、其他任务的等待/失败/未读完成，以及系统减少动态效果，都可能暂时覆盖当前任务的工作动画。

## 4. 日常安装 / 更新 / 诊断

```bash
cd /home/duang/xiaoleimi-codex-pet
git status --short --branch
git pull --ff-only
./install.sh
./scripts/verify-install.sh
```

若有本地改动，保留并先检查远端差异；不要 reset/clean 丢弃本地适配。素材安装无需关闭应用。运行时诊断为只读，退出码含义如下：

| 退出码 | 结果 | 下一步 |
| --- | --- | --- |
| 0 | 目标补丁精确匹配 | 若刚安装，重开应用并验收；不能据此宣称视觉已通过 |
| 1 | 素材缺失/不同或读取失败 | 查看错误，重新安装素材或修复输入 |
| 2 | 客户端未适配 / 缺少依赖 / 路径未知 | 保留标准 Pet；按下面流程适配 |
| 3 | 受支持原版，增强未安装或被更新覆盖 | 正常退出应用，从系统终端执行增强安装 |

运行时 `inspect` 只负责输出结构化状态，读取正常时即使不受支持也返回 0；需要自动判定时使用 `verify-install.sh` 的退出码或读取 JSON.status。

最终安装需要从系统终端执行，先正常退出 Codex，避免它继续使用缓存的 ASAR 头部与模块：

```bash
cd /home/duang/xiaoleimi-codex-pet
./install-with-runtime.sh
```

安装器会检查版本/指纹、生成并校验临时文件、校验完整原始备份、写入配套回滚 JSON，在再次确认原文件没有变化后，通过同目录原子重命名替换。系统目录写入时会使用 sudo。脚本不会关闭或重启应用，不会绕过进程检查。请不要同时运行客户端更新器或其他 ASAR 修改工具。

## 5. 升级后失效与恢复

- 应用更新覆盖补丁：诊断返回原版受支持或未适配；素材目录通常独立保留，但客户端仍须支持该图集格式。
- 文件指纹变化或补丁被其他修改混合：返回 `unsupported-or-mixed`，不重复替换字符串。
- 已补丁状态只接受完整目标模块哈希，不使用“存在几个关键词”作为成功依据。
- 回滚必须使用安装器生成的原始 ASAR 和同名 `.json` 配对记录，并匹配当前完整补丁 ASAR 的哈希与目标路径。
- 应用已经升级后，禁止把旧版备份覆盖到新版资源目录，否则 ASAR 与外部原生模块、unpacked 文件可能不匹配。改用当前版本官方安装包修复，再重新诊断。
- 历史备份若没有配套 JSON，本版恢复脚本会拒绝；需要单独核实整个版本，或直接使用当前版本官方安装包恢复。

正常退出应用后执行：

```bash
./scripts/restore-runtime.sh /实际备份路径/app.asar.版本.哈希
```

备份默认在 `${CODEX_HOME:-$HOME/.codex}/pet-runtime-backups/`；安装成功时打印确切路径。

## 6. 新版本适配流程

1. 读取当前应用版本，保留原始安装包与完整哈希。定位事件订阅、状态计算、通知传递、动画选择这四个环节，不能仅根据旧模块文件名搜索。
2. 新增独立版本适配器，记录原版模块路径模式、精确 SHA-256 和变换后 SHA-256。不同结构单独实现，不放宽既有适配器。
3. 审查事件 schema、导入/导出关系、React 依赖、等待和失败优先级、其他 Pet 的回退。避免把任意聊天内容当作指令或状态代码执行。
4. 在临时副本上生成补丁，检查目标块完整性、JavaScript 语法和所有非目标文件。保留 unpacked/link 元数据，确认平台是否有外部 ASAR 完整性或签名要求；本工具不会绕过签名机制。
5. 回归测试：思考→工具→思考→输出→完成，多工具并发、新 turn、等待、失败、减少动态效果、切换其他 Pet、重入安装、未知版本、单字节篡改。
6. 安装后人工验收表全部完成，才把矩阵从“静态/逻辑验证”升级为“界面验收通过”。附日期、应用版本、平台、补丁 ID；禁止把通过一个版本等同于所有未来版本可用。

测试不分发原始应用：

```bash

node --test scripts/runtime.test.js
XIAOLEIMI_TEST_ORIGINAL=/path/to/official/app.asar node --test scripts/runtime.test.js
```

第二条需要本适配器匹配的 `26.901.20858` 官方原始文件，已补丁文件不能作为输入。
