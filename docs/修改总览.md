# Xiaoleimi 修改总览

## 1. 为什么只复制 Pet 后动作不一样

Xiaoleimi 由两层组成：

1. Pet 包：`pet.json` 与 `spritesheet.webp`，负责角色、图集尺寸和全部动作素材。
2. 客户端运行时映射：负责判断当前是推理、工具执行、文字输出还是完成，并选择对应帧段。

官方自定义 Pet 是本机文件，不会自动同步到其他电脑。官方状态只有 Running、Needs input、Ready、Blocked；`pet.json` 没有配置细粒度事件到任意帧段的字段。因此，只迁移 Pet 包时，角色能出现，但会回到客户端内置的粗粒度动作映射。

## 3. 三个运行时模块的改动

### 3.1 会话状态计算模块

目标模块：`avatar-overlay-native-frame-*.js`

改动：

- 放宽 Running 判断：只要 `threadRuntimeStatus.type` 为 `active`、处于 resuming，或当前 turn 为 `inProgress`，就按运行中处理。
- 使用完整 turn items 判断最近事件。
- 识别工具类型：协作代理、命令、动态工具、文件修改、图片生成/查看、MCP、等待和网页搜索。
- 在工具与后续 reasoning 之间保存一个按会话隔离的短期工具阶段，避免工具执行结束后立刻误切为思考动作。
- 生成细分 `petState`：`T`、`Y` 或 `running`。
- 不再因为会话正好是当前打开页面就从浮动 Pet 活动源中排除它。
- Running 通知把 `petState` 交给动画组件，而不是固定传递 `running`。

### 3.2 浮动 Pet 页面数据传递模块

目标模块：`avatar-overlay-native-page-*.js`

改动：

- 会话 hook 从 `recent-conversations-meta` 切换为 `recent-conversations`，让映射层能看到 turn items 和实时状态。
- 把 `petState` 加入通知对象。
- 把 `petState` 加入通知变更签名，状态变化时会触发视图更新。

如果缺少这层，即使状态计算模块得出了 `T` 或 `Y`，显示层也收不到变化。

### 3.3 Pet 动画选择模块

目标模块：`codex-pet-assets-*.js`

改动只对 `custom:xiaoleimi` 生效：

| 运行时状态 | 触发依据 | Xiaoleimi 帧段 |
| --- | --- | --- |
| `T` | 最近事件为 reasoning，且不在工具阶段 | R7 C0–C2 |
| `running` | 工具正在执行、最近事件是工具，或运行中的兜底 | R7 C3–C5 → R8 C0 |
| `Y` | 最近事件为 agentMessage，或 final assistant output 开始后的 1.3 秒内 | R6 C0–C5 |
| `review` | 任务完成且有未读活动 | R7 C1–C5 |
| `waiting` | 需要授权、回答或用户决定 | R6 C0–C5 |
| `failed` | turn 失败或系统错误 | R5 C0–C7 |
| `idle` | 没有活动 | R0 C0–C5 |

另外，鼠标悬停仍由官方交互逻辑临时切换到 `jumping`，即 R4 C0–C4。R9/R10 是指针方向帧，只有渲染器启用 look frame 时才使用。

对于 R5 及之后的状态，修改后的选择器直接循环目标帧，不再把三轮目标动作与慢速 idle 尾帧拼接。这个变化解决了“任务执行期间大部分时间看起来仍像阅读/待机”的问题。

### 3.4 ASAR 完整性处理

三个模块保持原有字节长度，因此其他文件的 ASAR offset 不会变化。为了给新增逻辑腾出空间，转换过程压缩了动画尺寸常量、部分仅供翻译上下文使用的 message `description`，并移除三个目标模块尾部的 source-map 注释，再用无功能空白注释补齐原长度。界面消息正文没有被删除。

转换器随后重新计算三个模块的 SHA-256 与 ASAR block integrity，并更新头部。基于上述官方原始 ASAR 运行转换器，最终整个 ASAR 的 SHA-256 为：

```text
d00f41e78aedbd5ddf44a99fb36290da18876af26f91a6f163746bf75740ef81
```

## 4. 本机配置

当前机器还在 `${CODEX_HOME:-$HOME/.codex}/config.toml` 中选择了：

```toml
selected-avatar-id = "custom:xiaoleimi"
```

这项选择也是本机状态。迁移后建议从“Settings → Pets → Refresh → 小蕾米”重新选择，不建议脚本直接覆盖整个配置文件。

## 5. 风险和兼容边界

- 运行时补丁只验证了 Linux desktop `26.814.41407`。
- ChatGPT/Codex 更新会覆盖 `app.asar`；新版本模块名称、压缩变量或事件结构也可能改变。
- 补丁器会核对应用版本与三个模块的 SHA-256。任何一项不一致都会在写入前停止。
- 补丁器不会关闭、启动或重启 ChatGPT/Codex。
- 运行时修改不是 OpenAI 官方支持的 Pet 配置能力；标准 Pet 包仍可独立使用。

官方 Pets 的状态定义、创建流程和本地存储说明见 [OpenAI Pets 文档](https://developers.openai.com/codex/pets)。
